# SEO Audit — Mulak (mulak.app)

**URL audited:** https://www.mulak.app
**Date:** 2026-07-16
**Business type:** SaaS — AI property-management assistant for Dubai landlords (publisher: **Ganaken**)
**Method:** Full-site crawl + parallel specialist analysis (technical, content/E-E-A-T, schema, performance/CWV, GEO/AI-search, on-page, SXO). Free-tier data sources only — **no Google API / CrUX field data and no paid backlink data were available**, so Core Web Vitals and authority figures are lab/estimated, not real-user field data.

---

## Executive Summary

Mulak is a well-built, technically clean four-page marketing site sitting on top of a private Next.js/Vercel application. The engineering hygiene is genuinely good — server-side rendering, correct robots.txt, self-referential canonicals, HTTPS/HSTS, a valid sitemap, a well-formed `llms.txt`, and an optimized LCP hero image.

However, the site has **two serious credibility problems** and a **structural inability to be found in search**:

1. The Privacy Policy and Terms of Service are still published with the literal disclaimer *"This is placeholder text pending final legal review"* — on a product that handles rent, cheque and tenant data.
2. The structured-data pricing block tells Google and AI engines a flat **AED 1000** price, contradicting the on-page "free trial, then AED 1000/month, plus a custom tier" model — a structured-data misrepresentation.

Beyond those, the entire indexable footprint is 4 thin pages with no blog, guides, FAQ, or comparison content, no team/authorship or social-proof signals, and placeholder social links — so the site currently has almost no path to rank for its commercial keywords or to be cited by AI answer engines.

1. **Legal pages published as "placeholder text pending final legal review"** (Critical — trust & legal risk)
2. **Structured-data pricing misrepresents the real pricing model** (Critical — Google structured-data policy)
3. **Only 4 thin pages, no content strategy** — no route to rank for money keywords (High)
4. **No E-E-A-T / trust signals** — no team, reviews, testimonials, or real social presence (High)
5. **Missing security headers** (CSP, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy) (High)

### Top 5 Quick Wins
1. Delete the "placeholder text" sentence from `/privacy` and `/terms` today (stopgap while real legal copy is drafted).
2. Fix the homepage `<title>` — it duplicates the brand: "Mulak — Property Management for Dubai — **Mulak**".
3. Point the schema `url`/`publisher.url` at the www canonical and correct the `Offer` to reflect the free trial + monthly + custom tiers.
4. Remove the 3 unused preloaded font families (IBM Plex Sans, IBM Plex Mono, Space Grotesk) — ~3 fewer critical-path downloads, zero visual change.
5. Add `width`/`height` (or `aspect-ratio`) to every `<img>` to stop layout shift.

## 1. Technical SEO — Score 72/100

**What works**
- `robots.txt` is correct: allows the 4 public pages, disallows every authenticated app route (`/dashboard`, `/units`, `/tenants`, `/buildings`, `/cheques`, `/calendar`, `/network`, `/settings`, `/login`, `/signup`, `/verify-email`, `/auth/`, `/api/`), and declares `Host` + `Sitemap`.
- `sitemap.xml` is valid and lists all 4 public URLs.
- Canonical tags are present and self-referential on all 4 pages.
- HTTPS enforced; `http://` → `https://` returns 308; HSTS present (`max-age=63072000`).
- Trailing-slash policy consistent (`/about/` → 308 → `/about`).
- Clean, lowercase, parameter-free URLs.
- Mobile viewport meta present.
- Fully server-side rendered — not a blank SPA shell; crawlable in raw HTML.
- Custom 404 returns a proper 404 status.

**Findings**

| Severity | Finding | Evidence | Fix |
|---|---|---|---|
| High | Non-www HTTPS uses a **307 (temporary)** redirect to www | `https://mulak.app` → `307` → `https://www.mulak.app/`, while http variants use 308 | Force a permanent 301/308 in Vercel config so all host/protocol variants funnel to www permanently |
| High | Missing security headers | Only `Strict-Transport-Security` is set; no CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` on any route | Add via `next.config.js`/`vercel.json`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`, and a CSP (start report-only) |
| Medium | Public marketing pages are forced fully dynamic | Every route returns `cache-control: private, no-cache, no-store` and `x-vercel-cache: MISS`; disqualifies edge caching + bfcache | Make `/`, `/about`, `/privacy`, `/terms` static/ISR so Vercel serves cached `HIT`s; scope `no-store` to authenticated routes only |
| Medium | Auth routes are `Disallow`ed but not `noindex` | `/login` returns an indexable static 200 with no `noindex` | Add `noindex` meta/`X-Robots-Tag` to `/login`, `/signup`, `/verify-email` as defense-in-depth |
| Medium | HSTS lacks `includeSubDomains; preload` | `max-age=63072000` only | Extend header value and submit to HSTS preload list |
| Medium | 2-hop redirect for bare-HTTP apex | `http://mulak.app` → 308 → `https://mulak.app/` → 307 → www | Collapse to a single hop to `https://www.mulak.app/` |
| Low | Sitemap `lastmod` is request-time, identical across all URLs | All 4 URLs share `2026-07-16T18:27:09.871Z` | Tie `lastmod` to real content-edit timestamps, or drop it |
| Low | No web manifest / apple-touch-icon / theme-color | `/manifest.json`, `/apple-touch-icon.png` 404 | Add for PWA/mobile-chrome polish (not an indexing blocker) |
| Low | No IndexNow integration | No key file | Optional; low impact at 4 URLs |

## 4. Schema / Structured Data — Score 48/100

**What works**
- A single valid `SoftwareApplication` JSON-LD block (correct `@context`, non-deprecated type, required `name`/`operatingSystem`/`applicationCategory` present).
- No placeholder values in the schema; no fabricated `aggregateRating` (correctly withheld until real reviews exist).

**Findings**

| Severity | Finding | Evidence | Fix |
|---|---|---|---|
| **Critical** | `Offer` misrepresents the real pricing model | Schema states a flat `"price":"1000"` AED; on-page is "Start free, 14 days free, then from AED 1000/mo (Individual)" + "Custom, per portfolio (Business)". A parser reads this as a one-time AED 1000 and drops the Business tier | Model both tiers as an array of `Offer`s with `priceSpecification` (`unitCode: MON`), `eligibleDuration` (14-day trial), and no forced number on the custom tier |
| High | Schema `url`/`publisher.url` = non-www, through a redirect | Schema uses `https://mulak.app` while the canonical is `https://www.mulak.app` (and `https://mulak.app` 307-redirects) | Align all schema URLs to the www canonical |
| Medium | Identical commercial block duplicated on `/privacy` & `/terms` | The same `SoftwareApplication`+`Offer` block is byte-identical on all 4 pages (template bleed) | Remove it from legal pages; add `BreadcrumbList`/`WebPage` there instead |
| Medium | No `priceValidUntil` on the Offer | Absent | Add ISO-8601 `priceValidUntil` |
| Info | Missing `Organization` and `WebSite` schema | No site-wide entity nodes | Add `Organization` (with real `logo` + `sameAs` once social profiles exist) and `WebSite` (no fabricated `SearchAction` — no real site search exists) |
| Low | `operatingSystem: "Web"` non-idiomatic; `publisher` is a bare stub | No `logo`/`sameAs`/`@id` on the Organization | Use `"Web browser"`; reference a proper `Organization` node by `@id` |

> Note: FAQPage is **not** recommended for Google SERP benefit (rich results retired May 2026); it retains AI/entity-citation value only. HowTo is not recommended (deprecated 2023).

## 5. Performance / Core Web Vitals — Score 62/100

*No CrUX/field data available (PageSpeed API rate-limited, no Google API key). Findings are lab-estimated from headers, HTML, and downloaded assets.*

**What works**
- LCP hero (`dubai-skyline.webp`, 108 KB) is a WebP, preloaded with `fetchPriority="high"` — correctly optimized.
- TTFB measured fast (~190–250 ms).
- Below-fold images lazy-loaded appropriately.
- Healthy DOM (~553 elements, well under INP-risk thresholds).

**Findings**

| Severity | Finding | Evidence | Fix |
|---|---|---|---|
| High | CLS risk — all 7 `<img>` lack width/height | Hero `dashboard.png` container has no reserved aspect-ratio; Lighthouse "explicit width/height" audit will fail | Add explicit `width`/`height` (or CSS `aspect-ratio`) to every image |
| High | Oversized/unoptimized PNG screenshots (~1.28 MB total) | `network.png` 604 KB (1703×855), `unit.png` 391 KB (3258×902 for a small thumbnail), `calendar.png` 163 KB, `dashboard.png` 97 KB — all PNG, no `srcset` | Convert to WebP/AVIF (expect 60–80% reduction) and/or migrate to `next/image`; downscale `unit.png` |
| High | 9 preloaded fonts across 7 families; 3 families unused | ~189 KB of font preloads; IBM Plex Sans, IBM Plex Mono, Space Grotesk are preloaded but not referenced | Remove the 3 unused font imports — removes ~3 critical-path downloads, zero visual change |
| Medium | ~1.47 MB of JS across 17 chunks on a landing page | Sum of `/_next/static/chunks/*.js` | Audit for code-splitting; defer below-the-fold interactive chunks (animated network map) |
| Medium | `dashboard.png` doubles as the OG/Twitter image | `og:image`/`twitter:image` = the 97 KB in-page screenshot; no `og:image:width/height`; not 1200×630 | Generate a dedicated compressed 1200×630 OG image and declare dimensions |
| Medium | HTML `no-store` disqualifies bfcache | `preload_check.py` flags `cache_control_no_store: true` | Allow the public marketing pages to be cacheable/bfcache-eligible |
| Medium | "Network map" section is client-side-only | Raw SSR HTML shows `BAILOUT_TO_CLIENT_SIDE_RENDERING`; renders empty to non-JS crawlers | Server-render a text/image fallback for the diagram |

- Content is server-rendered — accessible to non-JS AI crawlers.
- Product screenshots carry descriptive alt text.

|---|---|---|---|
| High | Weak passage-level citability — no Q&A/definitional content | Zero question-phrased headings; `/about` body ~103 words in 1–2-sentence blurbs (far below the ~134–167-word citation sweet spot); no sourced stats | Add an FAQ section (8–12 question-format H2s, self-contained 134–167-word answers on pricing, cheque tracking, Arabic support, data security, RERA/Ejari) |
| High | No off-site brand/entity footprint | `linkedin.com/company/ganaken` = 404; zero third-party mentions for "mulak"; social links are placeholders → no valid `sameAs` possible | Build real LinkedIn/X/YouTube presence, then wire `sameAs`; pursue directory listings |

| Low | No RSL license reference in `llms.txt` | No `## License`/`rsl.txt` | Add an RSL 1.0 statement to future-proof AI-training licensing |
| Low | Brand-less sub-page titles reduce AI snippet disambiguation | `About`, `Privacy Policy`, `Terms of Service` | Add brand suffix |

## Prioritized Action Plan

### Phase 1 — Critical Fixes (Week 1)
- **Remove the "placeholder text pending final legal review" sentence** from `/privacy` and `/terms` immediately; commission real legal copy with UAE PDPL / data-residency language.
- **Correct the structured-data `Offer`** to reflect free trial + monthly + custom tiers, and point all schema URLs at the www canonical.
- Fix the duplicate-brand homepage `<title>`.

### Phase 2 — High-Impact Improvements (Weeks 2–3)
- Add the missing **security headers** (CSP report-only + `nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`); extend HSTS with `includeSubDomains; preload`.
- Make the non-www redirect **permanent (301/308)** and collapse the http-apex 2-hop chain.
- **Performance:** add image `width`/`height`, convert PNG screenshots to WebP/AVIF, remove the 3 unused font families, generate a dedicated OG image, make marketing pages edge-cacheable/bfcache-eligible.
- Create and link **real social profiles**; wire them into `Organization` schema `sameAs`; add an `Organization` + `WebSite` schema node.
- Link `/about` from the primary nav/footer (de-orphan it).

### Phase 3 — Content & Authority (Month 2)
- Launch a **`/blog` or `/resources`** section with UAE-specific landlord content (cheque-bounce law, RERA/Ejari renewals, rent-cap rules, tenancy contracts).
- Add an **FAQ section** (question-format headings, 134–167-word answers) for both SEO and AI-citation.
- Add **team/founder bios and proof points** (testimonials, pilot customers).
- Build persona/use-case pages and a comparison/alternatives page (SXO page-type coverage).
- Serve **Arabic on indexable URLs** with reciprocal `hreflang`.
- Add a demo **video** (YouTube) and a downloadable guide.

### Phase 4 — Monitoring & Iteration (Ongoing)
- Connect Google Search Console + GA4 and re-run with field (CrUX) data.
- Establish a drift baseline (`/seo drift baseline`) to catch regressions on deploys.
- Track: branded vs non-branded impressions, indexed-page count, AI-citation mentions, and Core Web Vitals field data.

### Falsifiability / leading indicators
- *Legal fix worked* → "placeholder" string no longer appears in `/privacy` or `/terms` source.
- *Pricing schema fixed* → Google Rich Results Test shows two Offers, no policy warning.
- *Content strategy working* → non-branded impressions in GSC begin to appear within 8–12 weeks of publishing resource content.
- *Authority building* → `linkedin.com/company/...` resolves; third-party brand mentions become indexable.
