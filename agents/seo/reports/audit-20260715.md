# SEO Audit — mulak.app

**Site:** https://www.mulak.app
**Audited:** 2026-07-15
**Business type:** SaaS (B2B software) — "Mulak", an AI assistant for Dubai landlords (property/portfolio management: units, tenants, post-dated-cheque tracking, rent & renewal reminders, WhatsApp alerts, ROI). Operated by **Ganaken**. Target market: Dubai / UAE. Bilingual EN/Arabic.
**Stack:** Next.js on Vercel. Site is essentially a single marketing landing page (anchors `#how`, `#features`, `#pricing`) plus `/about`, `/privacy`, `/terms`. The authenticated app (`/dashboard`, `/units`, `/tenants`, …) is correctly disallowed in robots.txt.
**Method:** Live crawl + 6 specialist sub-agents (technical, content/E-E-A-T, schema, performance, GEO/AI, SXO). All findings are evidence-backed from live responses on the audit date. Google field data (CrUX/Lighthouse) and paid backlink APIs were **not** available (no credentials), so all Core Web Vitals verdicts are lab/heuristic estimates, explicitly labeled.

A well-engineered, good-looking site with genuinely strong technical foundations (clean SSR, valid robots/sitemap, llms.txt, HTTPS) — but it is undermined by a small number of serious trust/crawl defects and, more fundamentally, by having almost nothing to actually rank: one thin landing page in a market where page-one is owned by multi-page vendor sites and listicles.

## Critical Findings (fix immediately — blocks trust, crawling, or ranking)

### C1. Live legal pages contain placeholder text
Both `/privacy` and `/terms` (dated "Last updated: 14 July 2026") contain the literal sentence **"This is placeholder text pending final legal review."** For a product marketed around handling tenants' financial data (rent, cheque images), publishing unfinished legal text is a trust-destroying and potentially liability-creating signal for humans, Google's quality raters, and AI systems alike. It directly contradicts the homepage's "bank-grade" claims.
**Fix:** Replace with finalized, UAE/DIFC-jurisdiction legal text reviewed by counsel before any further SEO/marketing push.

### C2. Soft-404 crawl trap — unknown URLs 307-redirect to `/login`
Any path that isn't an exact known route (and doesn't share a prefix with one) is caught by Next.js middleware and **307-redirected to `/login`**, which is itself `Disallow`-ed in robots.txt.
Evidence: `GET /this-page-does-not-exist-xyz → 307, location:/login`; `GET /foo-bar-baz → 307 /login`; `GET /ABOUT → 307 /login`. (By contrast, `GET /about-nonexistent → genuine 404`, proving the behavior is inconsistent by design.) Googlebot follows the 307, lands on a robots-blocked auth page, and reports a soft-404/redirect anomaly instead of a clean 404 — a crawl trap that can suppress crawl trust site-wide once any typo/old URL is discovered.
**Fix:** Narrow the auth middleware `matcher` to only the real app routes; route everything else to Next's `not-found.tsx` returning a true `404` (or `410`). Never redirect unknown marketing URLs into an auth wall.

### C3. Unsupported "bank-grade" security claims with no supporting page
The homepage claims **"Bank-grade data isolation"** and **"Bank-grade tenant isolation per client"**, but the footer "Security" link points to `#how` (a marketing anchor), not a real security page — none exists. A specific, checkable safety claim with zero linked evidence reads as misleading to buyers and quality raters, and is especially damaging for a fintech-adjacent product.
**Fix:** Build a real `/security` page (encryption in transit/at rest, hosting, data residency, access controls, incident response, any real certifications) — or soften the "bank-grade" language until it can be substantiated.

### C4. No indexable/informational content — thin site, no topical authority
The entire indexable site is ~1,183 words (home ≈572–611, /about ≈108–138, /privacy ≈218, /terms ≈216). There is **no blog, no FAQ, no guides, no glossary** — nothing addressing what Dubai landlords actually search (Ejari renewals, RERA rent cycles, PDC/cheque handling, ROI/yield methodology). The footer "Blog" link is fake (points to `#features`; no blog route exists). This starves both Google (topical authority) and AI engines (nothing citable — GEO citability scored 30/100).
**Fix:** Ship genuine educational content in question-led, self-contained ~130–170-word blocks (e.g., "How cheque tracking works for Dubai landlords," "Ejari renewal reminders explained," "How to calculate rental yield in Dubai"). This is the single highest-leverage fix for both SEO and AI citability.

### C5. Critical rendering path overloaded — likely LCP harm
The homepage floods the high-priority network path before the hero can paint: the HTTP `Link` header preloads **17 separate `.woff2` font files** (~365KB across 4 families), **and** preloads a **96.7KB off-screen `dashboard.png`** that sits below the hero — while the true LCP image (`dubai-skyline.webp`) has **no `fetchpriority="high"`** (`preload_check.py` scored 25/100). *(Lab/heuristic — no CrUX field data available.)*
**Fix:** Preload only the 1–2 above-the-fold fonts; remove the `dashboard.png` preload; add `fetchpriority="high"` to the hero image.

## High Findings (fix within ~1 week)

### H1. Page-type mismatch — a single landing page cannot rank for the money keywords
Live SERP sampling for "Dubai property management software" and "cheque tracking software UAE" shows ~8/10 results are **listicles ("Best X 2026") or multi-page vendor sites** (Keyper, PropSpace, MRI, Socienta, RealSoft) with dedicated feature/solution/city sub-pages. Mulak offers one 572-word page. The "Business/agency" persona it explicitly prices for scores 32/100 (unserved); comparison and compliance shoppers score 23/100.
**Fix:** Build a content hub of independently rankable pages: `/features/cheque-tracking`, `/features/rent-reminders`, `/for/property-managers` (agency page with indicative pricing + demo CTA), a "Mulak vs. spreadsheets" comparison page, and a UAE-compliance section referencing Ejari/RERA/DLD/VAT.

### H2. No indexable Arabic version + no hreflang
The EN/العربية toggle is a **client-side JS state swap on the same URL** — the raw HTML is `lang="en"` with exactly one Arabic string (the toggle label). AI crawlers and Google index only the English DOM. `og:locale` is `en` only; there are zero hreflang tags; `/ar` 307-redirects to `/login`. For a bilingual Dubai product this forfeits all Arabic-language search.
**Fix:** Serve Arabic on real SSR routes (`/ar`, `ar.mulak.app`) with `lang="ar" dir="rtl"`, `og:locale=ar_AE`, `hreflang` (`en`/`ar`/`x-default`), and sitemap entries.

### H3. Canonical vs. JSON-LD domain mismatch (www vs non-www)
Every page's `<link rel="canonical">` = `https://www.mulak.app`, but the JSON-LD `url` and `publisher.url` = `https://mulak.app` (non-www). Conflicting identity anchors hurt entity resolution.
**Fix:** Emit the `www` canonical form everywhere in the JSON-LD.

### H4. Non-www → www redirect uses 307 (temporary), not 301/308
`GET https://mulak.app/ → 307 → https://www.mulak.app/`. A temporary redirect discourages permanent link-equity consolidation onto the canonical host.
**Fix:** Make the apex→www redirect permanent (301/308) at the edge/DNS or via `redirects()` with `permanent: true`.

### H5. Broken / placeholder internal & footer links
Footer "Blog"→`#features`, "About Ganaken"→`#how` (a real `/about` exists but isn't linked), "Security"/"Data residency"→`#how`. On sub-pages these anchors resolve to nothing. Parsers found ~0–3 real internal links between indexable pages — no internal PageRank flow and wasted crawl budget on dead ends.
**Fix:** Point "About Ganaken" to `/about`; build or remove Blog/Security/Data-residency; use leading-slash absolute anchors; add contextual body links between Home/About/Privacy/Terms.

### H6. Large unoptimized PNG images, not long-cached
Measured: `network.png` **605KB**, `unit.png` **391KB**, `calendar.png` **163KB** (PNG screenshots, not WebP/AVIF). All `/landing/*` images serve `Cache-Control: public, max-age=0, must-revalidate` (revalidated every visit), unlike JS/CSS/fonts which are `immutable`.
**Fix:** Convert to WebP/AVIF with responsive `srcset` (~1MB+ savings likely); apply long-lived immutable caching to `/landing/*`.

### H7. Third-party SDK bundle → INP risk
One 330KB (decompressed) JS chunk bundles **HubSpot, Intercom, PostHog, and Sentry**, shipped to every marketing-page visitor (total JS ≈1.47MB decompressed). Heavy main-thread work during hydration is a documented INP risk. *(Estimate — no RUM/INP trace available.)*
**Fix:** Defer non-critical SDK init to `requestIdleCallback`/post-interaction; split chat/analytics SDKs out of the critical chunk.

### H8. Missing baseline security headers
Present: HSTS only. Absent: `X-Content-Type-Options`, `X-Frame-Options`, `Content-Security-Policy`, `Referrer-Policy`, `Permissions-Policy`. Not a direct ranking factor but dings Lighthouse Best-Practices and leaves clickjacking/referrer-leak exposure.
**Fix:** Add the headers via `next.config.js`/`vercel.json`; add `includeSubDomains; preload` to HSTS.

### H9. No trust/social proof; placeholder social links
No testimonials, customer logos, usage stats, or review-site presence (G2/Capterra/Trustpilot) — where every sampled competitor appears. Footer social icons link to bare platform roots (`x.com/`, `linkedin.com/`, `wa.me/`) with no handle.
**Fix:** Add real testimonials (name + portfolio size), claim G2/Capterra listings, fix or remove social links.

### H10. Zero external brand/entity signals (off-site)
A live web search for the Mulak/Ganaken brand returned essentially no external footprint — no Wikipedia, Reddit, YouTube, LinkedIn company page, Crunchbase, or press. AI engines have only the site's own claims to go on, so "what is Mulak" cannot be corroborated (platform-readiness estimates: AI Overviews 30, ChatGPT 35, Perplexity 30, Copilot 35).
**Fix:** Create a LinkedIn company page, a YouTube product demo (highest observed AI-citation correlation), a Crunchbase profile, and seed genuine community mentions (e.g., r/dubai, landlord forums).

### H11. Structured data: duplicated on legal pages, incomplete, no Organization/WebSite
The identical `SoftwareApplication`+`Offer` block is injected site-wide (root layout), so `/privacy` and `/terms` assert AED 1000/mo pricing irrelevantly. There is no standalone `Organization` (only nested `publisher`), no `WebSite` node, and the `Offer` is a flat `price:"1000"` that mismatches the visible plans (Free 14-day → from AED 1000/mo Individual; Custom Business) — no `priceSpecification`/`unitCode:MON`, no `AggregateOffer`.
**Fix:** Move `SoftwareApplication` to the homepage only; add referenced `Organization` + `WebSite` in the shared layout; model pricing with `priceSpecification`/multiple `Offer`s. Do **not** fabricate `aggregateRating` (no real reviews exist). Ready-to-paste `@graph` JSON-LD was produced by the schema pass.

### H12. Duplicate brand name in the title tag
`<title>Mulak — Property Management for Dubai — Mulak</title>` — brand appears twice (templating bug), wasting SERP real estate.
**Fix:** `Mulak — AI Property Management Software for Dubai Landlords`.

## Medium Findings (fix within ~1 month)

- **M1. HTML `no-store` + CDN caching disabled.** Marketing pages return `Cache-Control: private, no-cache, no-store` and `x-vercel-cache: MISS` on every request (edge round-trips Frankfurt→Washington-DC), inflating TTFB for the Dubai audience and disqualifying bfcache. Content is not personalized — scope `no-store` to app routes; add ISR/`force-static` for marketing pages.
- **M2. Render-blocking CSS, no critical-CSS inlining.** Two blocking stylesheets (~106KB + ~62KB) with no inline above-the-fold CSS. Inline hero/nav critical CSS; defer the rest.
- **M3. Fake sitemap freshness.** All four `lastmod` values are stamped to the exact request time (`2026-07-15T19:31:15.807Z`), not real edit dates — meaningless as a freshness signal. Emit `lastmod` from actual content-change dates.
- **M4. Thin `/about`, no company legitimacy signals.** ~108–138 words, no founder/team bios, no Ganaken registration/jurisdiction, no address/phone. Add real trust currency (team, DED/free-zone license, registered address).
- **M5. Weak keyword targeting.** The page never uses exact category phrases like "Dubai property management software" or "landlord software"; relies on "AI assistant for landlords." Add natural category + geo framing in an H2/lead paragraph.
- **M6. No FAQ / question-based headings.** All headings are benefit statements; no PAA/AI-Overview alignment. Add a genuine FAQ section (cost, security, cheque handling, cancellation, Arabic support) with `FAQPage` JSON-LD (for AI/LLM citation value — note Google retired FAQ rich results May 2026).
- **M7. `llms.txt` is thin.** Well-formed but lists only 4 pages with no pricing/feature facts and no `llms-full.txt`. Expand with concrete extractable facts.

## Low Findings (backlog)

- **L1.** HSTS lacks `includeSubDomains; preload`.
- **L2.** Hero image `alt=""` — correct if purely decorative; confirm intent.
- **L3.** No `width`/`height` on `<img>` tags — CLS mostly mitigated by CSS layout, but add explicit dimensions/`aspect-ratio` to the dashboard image container.
- **L4.** No `<script type="speculationrules">` to prefetch/prerender likely next navigations.
- **L5.** No visible "last updated" dates on pages (minor freshness signal for AI trust).
- **L6.** Training crawlers (CCBot, anthropic-ai, cohere-ai) are unblocked by the wildcard — a deliberate decision, not a defect; block explicitly only if training opt-out is desired.

## Prioritized Action Plan

Each action notes its dependency, a falsifiability check ("how we'd know it failed"), and a leading indicator to monitor without re-running the audit.

**Phase 1 — Stop the bleeding (trust & crawl integrity), this week**
1. **Replace placeholder legal text** (C1). *Depends on:* legal counsel. *Failed if:* the phrase "placeholder text" still appears in `/privacy` or `/terms`. *Watch:* manual page check.
2. **Fix the soft-404 crawl trap** (C2) — scope middleware, return real 404s. *Unblocks:* clean crawling of everything below. *Failed if:* `curl -I /random-xyz` still returns 307→/login. *Watch:* GSC "Page Indexing" → soft-404/redirect counts.
3. **Ship a real `/security` page or soften "bank-grade"** (C3). *Failed if:* the "Security" link still targets `#how`. *Watch:* click path from footer.
4. **Fix footer/internal links + duplicate title + JSON-LD www URL** (H5, H12, H3) — cheap, same deploy. *Failed if:* "About Ganaken" still points to `#how`. *Watch:* internal-link count in a crawl.

**Phase 2 — Make the site rankable, weeks 2–6**
5. **Build the content hub + FAQ** (C4, H1, M6): feature pages, `/for/property-managers`, a comparison page, a UAE-compliance section, and an FAQ. *Depends on:* #2 (clean crawling). *Failed if:* indexable word count/URL count doesn't materially grow. *Watch:* GSC indexed-page count; impressions for RERA/Ejari/comparison queries.
6. **Ship indexable Arabic** (H2) with hreflang. *Depends on:* routing work from #2. *Failed if:* `curl /ar` doesn't return SSR Arabic HTML. *Watch:* impressions on Arabic queries.
7. **Add trust/social proof + external brand footprint** (H9, H10): testimonials, G2/Capterra, LinkedIn, a YouTube demo. *Failed if:* brand search still returns no external results. *Watch:* branded-search impressions; referral traffic.

**Phase 3 — Performance & polish, weeks 4–8**
8. **Fix the rendering path** (C5): trim font preloads, drop the off-screen image preload, add hero `fetchpriority`. *Failed if:* `preload_check.py` score stays ≤25. *Watch:* CrUX LCP once field data accrues.
9. **Optimize images + caching** (H6, M1, M2): WebP/AVIF, immutable `/landing` caching, scope `no-store` off marketing routes, inline critical CSS. *Watch:* total page transfer weight; TTFB from a UAE location.
10. **Security headers, schema `@graph`, SDK deferral, sitemap `lastmod`, `/about` depth** (H8, H11, H7, M3, M4). *Watch:* Lighthouse Best-Practices score; Rich Results Test on the homepage.
